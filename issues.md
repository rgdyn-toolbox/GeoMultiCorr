# Redundant parts
- Here we look for code blocks with the same objective, but written in a different ways across our the DC and TD's branches
- [ ] Image management strategy
	- TD's version rely on Telenvi
		- Pros : 
			- TD is very familiar with this lib
		- Cons : 
			- It is not very well documented
			- And not available online with pip or conda
	- DC's version on rasterio + geo_utils
- [ ] File location during correlation
	- ASP generate a lot of files and images during the correlation.
	- TD's version 
		- These files are created in the software directory, under ./temp/ and then move everything towards the user project folder (Session.p_root attribute). 
		- Pros
			- Works as a charm on any external hardrives
		- Cons
			- One additional step : move the data after the correlation
				- (Pair.save_corr_data())
	- DC's version
		- Files are directly created on the project folder. 
			- PRos : simple logic
			- Cons : not working when the project folder is stored on a external hardrive fat32 because of the symlinks generated by ASP.
